# 15. 3Sum

Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set must not contain duplicate triplets.

### Example 1:
**Input:** nums = [-1,0,1,2,-1,-4]
**Output:** [[-1,-1,2],[-1,0,1]]
**Explanation:** 
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
The distinct triplets are [-1,0,1] and [-1,-1,2].
Notice that the order of the output and the order of the triplets does not matter.

### Example 2:
**Input:** nums = [0,1,1]
**Output:** []
**Explanation:** The only possible triplet does not sum up to 0.

### Example 3:
**Input:** nums = [0,0,0]
**Output:** [[0,0,0]]
**Explanation:** The only possible triplet sums up to 0.

### Constraints:
- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

- **Confirm input/output:**

  - Output: A list of lists, where each inner list contains exactly 3 integers that sum to 0.

- **Basic understanding:** The problem is asking me to find 3 numbers `A + B + C = 0`. The trickiest part is definitely going to be making sure my code doesn't output duplicate answers (like returning `[-1, 0, 1]` twice just because there are two `-1`s in the array). 

# Understanding the Constraints

What the constraints are secretly telling me:
- **Time complexity:** `nums.length <= 3000`. This is the most important constraint! It tells me that an $O(n^2)$ algorithm will take roughly $3000 \times 3000 = 9,000,000$ operations, which easily passes the typical $10^8$ operations per second limit on LeetCode. So, I am looking for an $O(n^2)$ solution.
- **Space complexity:** The problem doesn't explicitly restrict space, but standard algorithms can do this in $O(1)$ auxiliary space (ignoring the space required for the output list of lists and the sorting algorithm under the hood).
- **What algorithm to use:** $O(n^2)$ Time + finding sums = **Sorting + Two Pointers!**

# Solution 

## Brute Force (Three Loops)

- **Intuition:** The most basic way to find 3 numbers is to just use 3 nested loops to check every single combination in the array. 
- **Pseudo code:**
```text
SET result = new HashSet to prevent duplicates
FOR i from 0 to n-1:
    FOR j from i+1 to n-1:
        FOR k from j+1 to n-1:
            IF nums[i] + nums[j] + nums[k] == 0:
                result.add(sorted([nums[i], nums[j], nums[k]]))
RETURN result
```
- **Time Complexity:** $O(n^3)$ because of the three nested loops. This will 100% give a Time Limit Exceeded (TLE) since $(3000)^3 = 27,000,000,000$ operations.
- **Space Complexity:** $O(\text{number of triplets})$ because we use a HashSet to weed out duplicates.
- **Thoughts:** We need to get this down to $O(n^2)$. 

## Optimized Code (Sorting + Two Pointers)

- **Intuition:** `3Sum` is literally just `Two Sum II (Sorted Array)` in disguise! If we sort the array first, we can run a single `for` loop to lock in our first number (let's call it `A`). Now, we just need to find two *other* numbers `B` and `C` in the rest of the array such that `B + C = 0 - A`. Since the rest of the array is sorted, we can use our $O(n)$ Two Pointer approach (one pointer at the start, one at the end) to find `B` and `C`!
  
  *How to avoid duplicates?* Because the array is sorted, identical numbers sit right next to each other. Whenever we step onto a number we've already seen, we just `continue` and skip it!
- **Pseudo code:**
```text
1. Sort the nums array
2. SET result = empty list

3. FOR i from 0 to length - 1:
4.     // Skip duplicate 'A's
5.     IF i > 0 AND nums[i] == nums[i-1]: CONTINUE
6.
7.     // Standard Two Pointer setup
8.     SET left = i + 1
9.     SET right = length - 1
10.    
11.    WHILE left < right:
12.        SET sum = nums[i] + nums[left] + nums[right]
13.        
14.        IF sum > 0: right--
15.        ELSE IF sum < 0: left++
16.        ELSE:
17.            result.add([nums[i], nums[left], nums[right]])
18.            left++ // Keep searching for more pairs!
19.            // Skip duplicate 'B's to avoid duplicate triplets
20.            WHILE left < right AND nums[left] == nums[left-1]: left++

21. RETURN result
```
- **Time Complexity:** $O(n \log n)$ to sort + $O(n^2)$ for the nested loops = **$O(n^2)$** overall time. Perfect for our constraints!
- **Space Complexity:** $O(1)$ auxiliary space (or $O(\log n)$ to $O(n)$ depending on the language's sorting algorithm under the hood).
- **Solution Code (Java):**
```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        
        // 1. Sort the array so we can use Two Pointers and easily skip duplicates
        Arrays.sort(nums);
        
        for (int i = 0; i < nums.length; i++) {
            // If the first number is > 0, the sum can NEVER be 0 (since array is sorted)
            if (nums[i] > 0) break;
            
            // Skip duplicate 'A' numbers so we don't build duplicate triplets
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            
            // Standard Two Pointer approach for the rest of the array
            int left = i + 1;
            int right = nums.length - 1;
            
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                
                if (sum > 0) {
                    right--; // Sum is too big, shrink from the right
                } else if (sum < 0) {
                    left++; // Sum is too small, grow from the left
                } else {
                    // We found a triplet!
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    
                    // We need to keep searching for more pairs for this 'A'
                    left++;
                    
                    // Skip duplicate 'B' numbers so we don't build duplicate triplets
                    while (left < right && nums[left] == nums[left - 1]) {
                        left++;
                    }
                }
            }
        }
        
        return result;
    }
}
```

# Mistakes & Corrections

Things to remember for this specific problem (it's a trap for bugs!):

1. **Forgetting to skip duplicates for BOTH pointers:**
   - *My mistake:* I skipped duplicate `nums[i]` but forgot to skip duplicate `nums[left]` inside the `else` block. 
   - *Correction:* If my array is `[-2, 1, 1, 1]`, and I find the triplet `[-2, 1, 1]`, if I just move `left++` once, `left` points to another `1`, and I'll add `[-2, 1, 1]` again! I must `while (nums[left] == nums[left-1]) left++` after finding a successful pair!

2. **Breaking early optimization:**
   - *Pro-tip:* If `nums[i] > 0`, you can immediately `break` out of the main loop. Why? Because the array is sorted! If the smallest number in your triplet is already greater than 0, there is no way adding two larger numbers will ever get you back down to 0. 

3. **Moving pointers after finding a triplet:**
   - *My mistake:* After adding a triplet to the result, I forgot to move `left++` or `right--` and my code got stuck in an infinite `while` loop!
   - *Correction:* Always remember to advance at least one pointer after a successful hit before running your duplicate-skipping `while` loop.
